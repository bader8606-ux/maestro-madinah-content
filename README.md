# مايسترو — إدارة محتوى شاشات المدينة

واجهة عربية RTL لإدارة مصنف Excel المرجعي، مع حسابات محمية من التحرير العرضي، ومعاينة الاستيراد، وتصدير XLSX ونسخ JSON احتياطية. الكود العام لا يحتوي المصنف أو بياناته؛ تُحمَّل البيانات بعد التحقق من العضوية في مساحة Supabase الخاصة.

## حالة التسليم

نُشرت الواجهة على https://bader8606-ux.github.io/maestro-madinah-content/ وربطت بمشروع Supabase المستقل. طُبّقت الجداول والإجراءات وحُمّل المرجع في المساحة الخاصة. حساب المالك مفعّل والتسجيل العام مُغلق. تحقّق تسجيل الدخول الفعلي، والحفظ ووصول التحديث إلى جلسة ثانية تلقائيًا، واستعادة البيانات بعد إعادة فتح الصفحة، والتصدير والنسخ الاحتياطي من الموقع المنشور. لم تُرفع بيانات المصنف إلى GitHub.

## التشغيل والبناء

يتطلب Node.js 22 أو أحدث وpnpm أو npm.

```sh
pnpm install --frozen-lockfile
pnpm run check
pnpm run build
python3 -m http.server 8770 --bind 127.0.0.1 --directory dist
```

افتح http://127.0.0.1:8770 . بدون الإعدادات العامة الصالحة تظهر رسالة أن الربط غير مكتمل، ولا يُدَّعى حفظ البيانات.

## إعداد Supabase

1. اختر مشروعًا معتمدًا داخل حسابك، أو أنشئ مشروعًا جديدًا بعد اختيار المؤسسة والتحقق من تكلفته. لا تتطلب ملفات المصدر شراء خطة مدفوعة.
2. طبّق `supabase/migrations/0001_workspace.sql` من SQL Editor. لا تُطبّقها على قاعدة غير معروفة دون فحص الجداول أولًا.
3. عطّل التسجيل العام، وأنشئ حساب مالك المشروع من Authentication → Users. أدخل كلمة المرور بنفسك في Supabase؛ لا تحفظها في GitHub أو ملفات الإعداد.
4. لإنشاء تثبيت جديد فارغ، استخدم `supabase/bootstrap.example.sql` بعد استبدال البريد بعنوان المالك الحقيقي. هذا المثال يُنشئ مساحة جديدة؛ لا تُعد تشغيله على التثبيت الحالي. لإضافة مالك أو عضو للتثبيت الحالي، اربط معرّف مستخدم Auth بالمساحة الموجودة في `dist/config.js` عبر حساب المسؤول في SQL. لا يمنح تسجيل الدخول وحده وصولًا إلى أي مساحة.
5. اضبط `dist/config.js` بعنوان المشروع ومفتاح **publishable** العام ومعرّف المساحة فقط. لا تستخدم `service_role` أو `sb_secret_` أو كلمة مرور قاعدة البيانات في الواجهة أو المستودع.
6. سجّل الدخول إلى الموقع واستورد المصنف الأصلي من الجهاز. راجع معاينة الخلايا ثم أكّد الحفظ. لا تضع المصنف في GitHub ولو كان المستودع خاصًا.
7. لإضافة أعضاء، أنشئ حساباتهم في Authentication ثم أضف عضويتهم عبر حساب المسؤول في SQL. الأدوار: `owner` و`editor` و`viewer`. لا تمنح تعديل جدول العضويات لمستخدمي الواجهة.

جميع جداول التطبيق محمية بـRLS. لا تُمنح الأدوار العامة كتابة مباشرة؛ تمر العمليات عبر إجراءات تتحقق من العضوية والدور، وتقفل السجل وتقارن رقم المراجعة داخل معاملة واحدة. يحتفظ سجل التعديلات بنسخ سابقة للتراجع. الحسابات الإدارية في Supabase تظل قادرة على الإدارة وفق صلاحيات المنصة.

## GitHub Pages

استخدم مستودعًا مستقلًا لهذا الموقع حتى لا تستبدل موقعًا منشورًا لمشروع آخر. ادفع **محتويات هذا المجلد فقط**، مع استبعاد `node_modules` وكل المصنفات وقواعد البيانات والاختبارات الخاصة. ملف `.gitignore` حاجز إضافي، وليس بديلًا عن مراجعة الملفات قبل الدفع.

مصدر Pages مضبوط على `main` ومجلد `docs/`. بعد ضبط `dist/config.js` أو تعديل المصدر، شغّل `pnpm run build`؛ يبني المحرك وينسخ محتويات `dist/` إلى `docs/` تلقائيًا. ارفع التغييرات إلى GitHub لينشرها Pages. الروابط في الواجهة نسبية وتعمل تحت مسار المستودع. لا تنشر `source` أو `data` أو ملفات QA أو ZIP النسخ الاحتياطية. إعدادات Supabase العامة في config ليست سرًا؛ حماية البيانات تعتمد على Auth وRLS وإجراءات العضوية، لا على إخفاء المفتاح العام.

## الحفظ والتزامن

- لا يظهر نجاح الحفظ إلا بعد نجاح قاعدة البيانات. تُحمّل البيانات من المساحة عند فتح الموقع بعد تسجيل الدخول.
- تُفحص التحديثات كل 15 ثانية أثناء ظهور الصفحة وعدم فتح نموذج. يوفّر زر «تحديث البيانات» تحديثًا مباشرًا.
- إذا حفظ جهاز آخر أثناء تحرير نموذج، تُرفض المراجعة القديمة؛ لا يُدمج تعارض الحقول تلقائيًا. ألغِ النموذج، وحدّث البيانات، ثم أعد التعديل.
- التراجع يستعيد النسخة السابقة في مراجعة جديدة ويُسجّل كعملية مستقلة. استعادة نسخة احتياطية تستعيد البيانات وتضيف عملية للسجل؛ لا تستبدل سجل الأحداث المشترك بتاريخ الملف المستعاد.
- لا يوجد حفظ للعمل دون اتصال. رمز الجلسة فقط يبقى في المتصفح؛ لا تُحفظ بيانات المصنف في localStorage.

## منطق Excel والحدود

يدعم المحرك الورقتين `Sheet1` و`Sheet2`، ومراجع الخلايا والنطاقات و`SUM` والجمع والطرح والضرب والقسمة والأقواس المستخدمة في المرجع. تُرفض البنية أو المعادلات غير المدعومة بوضوح. لا تُشغّل macros أو تعليمات داخل الملفات.

تبقى الورقتان مستقلتين، وتُحفظ المراجع المطلقة والخلايا الناقصة وعيوب المصدر الأصلية كما هي وتُعرض كملاحظات. الحذف يفرّغ خلايا السجل مع إبقاء صفه لحماية المراجع؛ الإضافة تدرج صفًا قبل الإجمالي وتحدّث المراجع. يحافظ التصدير على باقي أجزاء حزمة OOXML ويعيد حساب النتائج المدعومة. حماية المعادلات هنا تمنع التحرير العرضي في الواجهة؛ يظل محرّر المساحة المخوّل قادرًا على استيراد مصنف محدث بعد معاينته.

الحد التقني للملف المستورد 10MB، ويشمل النسخة الاحتياطية JSON. لا تدخل أدوات الخطوط أو الشعار أو المكتبات من CDN أثناء الاستخدام؛ كلها مع ملفات الموقع.

## التحقق قبل التسليم الحي

تمت مقارنة محرك المتصفح مع المصنف ومحرك Python مستقل: المعادلات الأصلية الـ277، والعمليات، والتصدير وإعادة الاستيراد، ومطابقة الأجزاء الأخرى من OOXML. توجد أيضًا اختبارات محاكاة للجلسات وعمليات الحفظ والتعارضات. ملفات الاختبار التي تحتوي البيانات بقيت خارج هذا المجلد العام.

على Supabase الفعلي نجحت مؤشرات الصلاحيات الـ11، ورُفضت قراءة الزائر المجهول والوصول إلى المخطط الخاص. نجح دخول حساب المالك والحفظ والتحديث التلقائي في جلستين وإعادة الفتح، ثم تنزيل Excel ونسخة JSON احتياطية. المصنف المصدّر من الموقع يضم المعادلات الـ277 والسجلات الـ130، دون اختلاف في المدخلات أو المعادلات عن المرجع. جرى اختبار الحفظ بإعادة حفظ القيم الحالية.

اختبارات الأدوار الأخرى والتعارض والتراجع والاستيراد شملت PostgreSQL محليًا ومحاكاة واجهة API؛ لم تُنشأ حسابات فريق إضافية لهذا الاختبار. يلزم التحقق من أدوار الأعضاء عند إضافتهم. التحقق من المزامنة أُجري في تبويبين مستقلين على المتصفح، وليس على جهازين ماديين.
